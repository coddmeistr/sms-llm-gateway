# SMS LLM Gateway

Android-приложение, которое превращает телефон с SIM-картой и интернетом в SMS-шлюз к LLM:

1. любой телефон отправляет SMS на номер SIM-карты телефона-шлюза;
2. приложение принимает SMS;
3. отправляет текст в OpenAI-compatible Chat Completions API;
4. возвращает ответ отправителю обычной SMS.

## Как собрать

1. Откройте папку `sms-llm-gateway` в Android Studio.
2. Дождитесь Gradle Sync.
3. Подключите Android-телефон с SIM-картой.
4. Соберите и установите debug APK через Android Studio.

Если Android Studio попросит установить Android SDK 35 или Gradle plugin зависимости, согласитесь.

## Как настроить

На телефоне-шлюзе:

1. Откройте приложение `SMS LLM Gateway`.
2. Разрешите `RECEIVE_SMS`, `SEND_SMS` и `READ_PHONE_STATE` (приложение запросит все три).
3. На главном экране включите `Шлюз включен`.
4. При необходимости откройте `Настройки`.
5. Оставьте `LLM endpoint` по умолчанию: `https://openrouter.ai/api/v1/chat/completions`.
6. `API key` уже подставляется из сборки. При необходимости его можно заменить вручную.
7. Оставьте Model по умолчанию: `openrouter/auto`.
8. Выберите пресет системного промпта (default / coder / brief / tutor / translator / writer / expert).
9. При необходимости заполните список разрешенных номеров.

Настройки сохраняются автоматически после изменения. Большинство параметров можно менять и по SMS.

После этого отправьте SMS на номер телефона-шлюза. Ответ придет с этого же номера.

## SMS-команды

Команды регистронезависимые. Можно ставить необязательный префикс `/` или `!`.
Разделители между ключом и значением — пробел, `=` или `:`. Все «глаголы»:
`HELP STATUS RESET GET SET LIST CHAT MODEL PRESET TOKENS THINK WEB TEMP CHARS`.
Все остальные SMS считаются обычным сообщением в LLM.

### Универсальный синтаксис

- `HELP` — список команд (короткий).
- `STATUS` — текущий чат, модель, пресет, лимиты, флаги.
- `GET` — все настройки одним SMS.
- `GET <ключ>` — одно значение. Ключи: `preset`, `model`, `tokens`, `temp`, `think`, `web`, `chars`, `chat`.
- `SET <ключ> <значение>` — установить. Примеры: `SET preset coder`, `SET tokens 300`, `SET think on`.
- `LIST presets` — список пресетов.
- `LIST models` — нумерованный список моделей.
- `RESET` — сбрасывает per-sender настройки (model, tokens, temp, think, web). Чаты не трогает.

### Короткие алиасы

- `PRESET <имя>` — выбрать пресет (`default | coder | brief | tutor | translator | writer | expert`).
- `MODEL <N|id>` — выбрать модель по номеру или id.
- `MODEL LIST` — список моделей.
- `MODEL INFO <N>` — подробности (полный id, поддержка thinking).
- `MODEL USE <id>` — выбрать любую модель по id, даже если её нет в списке.
- `TOKENS <N>` — лимит токенов от модели (50–2000). Чем меньше, тем короче ответ.
- `TEMP <0.0-2.0>` — температура. Десятичный разделитель `.` или `,`.
- `THINK on|off` — включить thinking-режим (работает на моделях с поддержкой reasoning).
- `WEB on|off` — включить web search через OpenRouter plugin.
- `CHARS <N>` — лимит длины SMS-ответа (100–1500 символов).

### Чаты

- `CHAT LIST` — список чатов.
- `CHAT NEW <имя>` — создать и выбрать чат.
- `CHAT USE <имя>` — переключиться.
- `CHAT CLEAR` — очистить историю текущего чата.
- `CHAT DELETE <имя>` (синонимы `DEL`, `REMOVE`, `RM`) — полностью удалить чат и его историю. Чат `main` удалить нельзя; если удалить активный — текущим станет `main`.

### Whitelist разрешенных номеров

- `ALLOWED` или `ALLOWED LIST` — показать текущий whitelist.
- `ALLOWED ADD <номер>` — добавить номер. Номер можно писать в любом формате (`+7 (912) 123-45-67`).
- `ALLOWED DEL <номер>` (синонимы `REMOVE`, `RM`) — убрать номер.
- `ALLOWED CLEAR` — очистить whitelist целиком, шлюз станет принимать SMS со всех номеров.
- `ALLOWED SET <номер[,номер...]>` — задать список целиком, заменяя текущий. Разделители — запятая или точка с запятой.
- Универсальные формы тоже работают: `GET allowed`, `SET allowed +79121234567,+79122223344`.

Будьте осторожны: можно случайно вычеркнуть себя из whitelist. Если whitelist окажется пустым — шлюз снова начнёт пропускать SMS со всех номеров (как до настройки).

Синонимы on/off: `on/off`, `1/0`, `yes/no`, `y/n`, `+/-`, `true/false`, `вкл/выкл`, `да/нет`.

### Несколько команд в одной SMS

Чтобы сэкономить на отправке нескольких SMS при настройке, команды можно объединить в одно сообщение через разделитель `&&`. Команды выполняются последовательно слева направо, в ответ приходит нумерованный список результатов.

```
PRESET coder && TOKENS 400 && THINK on && STATUS
```

Ответ:

```
1) preset=coder
2) tokens=400
3) think=on
4) Чат: main. Модель: ... . Preset: coder. Tokens: 400. Temp: 0.70. Think: on. Web: off. Chars: 800.
```

Правила:

- Пробелы вокруг `&&` необязательны: `PRESET coder&&TOKENS 400` тоже работает.
- Пустые сегменты (`&&PRESET coder&&`) пропускаются.
- Если в SMS вообще нет `&&` — поведение прежнее, никакого батч-режима.
- Батч-режим — это «макрос настроек»: ни один сегмент не уходит в LLM. Если какой-то сегмент не распознан как команда (например `STATUS && привет`), для него в ответ придёт пометка `N) не команда: ...`, а остальные команды всё равно выполнятся.
- Аргументы команд не должны содержать `&&` (телефонные номера, id моделей, имена пресетов и чатов так и так не содержат, ограничение чисто теоретическое).

### Одноразовые маркеры в SMS

Внутри обычного сообщения (не команды) можно вписать маркеры `[WEB]` и/или `[THINK]` — они включат соответствующую опцию **только для этого запроса**, даже если глобально она выключена.

- `[WEB] какая сегодня погода в Москве` — разовый web-поиск.
- `[THINK] объясни задачу шаг за шагом: ...` — разовый reasoning-режим.
- `[WEB][THINK] сравни цены ...` — обе опции сразу.

Маркеры регистронезависимы (`[web]`, `[Think]` работают). Допускаются пробелы внутри скобок (`[ WEB ]`). Сами маркеры в текст для LLM не попадают. Если в SMS оказались **только** маркеры без текста — придёт подсказка «добавьте сам вопрос». Маркер может **включить** опцию, но не выключит ту, что уже включена в настройках.

### Какие настройки где

- **Глобальные** (одни для всего шлюза): `preset`, `chars`, `endpoint`, `api_key`, `allowed_senders`, `model` (как fallback).
- **Per-sender** (свои у каждого номера отправителя): `model`, `tokens`, `temp`, `think`, `web`, активный чат, история сообщений.

## Тест на эмуляторе

На Android Emulator можно проверить прием SMS, настройки, команды и запрос к LLM без физической SIM:

1. В Android Studio выберите эмулятор и нажмите `Run`.
2. В приложении разрешите SMS-доступ, включите `Шлюз включен` и нажмите `Сохранить настройки`.
3. Нажмите `Тест LLM без SMS`, чтобы проверить интернет, ключ, endpoint и модель.
4. Откройте `Device Manager`.
5. Рядом с запущенным эмулятором нажмите `...` или `Extended Controls`.
6. Откройте раздел `Phone`.
7. В `From` укажите тестовый номер, например `79001234567`.
8. В `Message` отправьте `HELP`, затем обычный вопрос.

На эмуляторе приложение не пытается отправлять исходящие SMS через виртуальный модем. Вместо этого ответ записывается в `Последний статус`, например `Эмулятор: SMS-ответ не отправлен. Ответ: ...`. На физическом телефоне с SIM ответ будет отправляться настоящей SMS.

## Тесты

Юнит-тесты лежат в `app/src/test`. Запуск:

```
./gradlew test
```

Покрытие:

- `TextSanitizerTest`, `PhoneMatcherTest`, `PromptPresetsTest`, `ModelCatalogTest`, `LlmMarkersTest` — pure Java.
- `LlmClientResponseParserTest` — парсинг OpenAI-compatible JSON-ответов (включая мультимодальные content-массивы, reasoning, refusal, top-level text).
- `commands/CommandParserTest`, `commands/CommandRouterTest` — гибридный синтаксис SMS, валидация значений, выбор моделей.
- `ConversationStoreRobolectricTest`, `commands/PrefsSettingsGatewayRobolectricTest` — Robolectric, проверяют сохранение/чтение SharedPreferences, изоляцию per-sender, дефолты, лимиты и `RESET`.

## Важные ограничения

- За входящие и исходящие SMS может взиматься плата оператором.
- Длинные ответы дробятся на несколько SMS. На некоторых Pixel-сборках без `READ_PHONE_STATE` стандартный `divideMessage` бросает `SecurityException: getGroupIdLevel1`; в этом случае приложение автоматически переходит на ручную нарезку.
- Для публикации в Google Play SMS-разрешения требуют специального обоснования; для личного использования проще устанавливать APK напрямую.
- OpenRouter free-модели подходят для тестов и низкой нагрузки, но у них есть rate limits и доступность может меняться.
- API key попадает внутрь APK и хранится локально в настройках приложения. Для продакшена лучше не вшивать ключ в клиентское приложение, а добавить свой backend-прокси или хотя бы шифрование и PIN/биометрию.
- Приложение рассчитано на OpenAI-compatible `/v1/chat/completions` API.
- Thinking (`reasoning`) и web search (`plugins:[{id:"web"}]`) реализованы через расширения OpenRouter — на других провайдерах эти параметры просто игнорируются.
